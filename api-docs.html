Authentication

เรียก login ก่อนใช้งานข้อมูล API; `login`, `logout`, `me` เป็น public endpoint. รหัสผ่านผู้ดูแลระบบอ่านจาก environment variable APP_ADMIN_PASSWORD.

POST ?action=login

{
  "username": "admin",
  "password": "<APP_ADMIN_PASSWORD>"
}

สำเร็จ: 200 และ {"user":{"name":"ผู้ดูแลระบบ"}}; login ไม่ผ่าน: 401.

GET ?action=me

ส่งคืนผู้ใช้ปัจจุบัน หรือ {"user":null} เมื่อยังไม่ login.

GET ?action=logout

จบ session และส่งคืน {"ok":true}.

Read endpoints

GET ?action=list&entity={entity}&q={search}&limit={limit}

ค้นหารายการด้วย q; limit เริ่มต้น 200 และถูกจำกัดในช่วง 1–500. entities ที่รองรับ:

Entityข้อมูลหลักเขียนได้
productsชื่อสินค้า, ผู้ขาย, หมวดหมู่, หน่วย, ราคาCRUD
categoriesชื่อและรายละเอียดหมวดหมู่CRUD
ordersวันที่, ลูกค้า, พนักงาน, ขนส่ง, ยอดรวมCRUD
orderdetailsคำสั่งซื้อ, สินค้า, จำนวนCRUD
customersชื่อ, ผู้ติดต่อ, ที่อยู่, เมือง, ประเทศCRUD
suppliersบริษัท, ผู้ติดต่อ, ที่อยู่, โทรศัพท์CRUD
employeesชื่อ, วันเกิด, รูป, หมายเหตุCRUD
shippersบริษัทขนส่งและโทรศัพท์CRUD

ตัวอย่าง: GET ?action=list&entity=products&q=tea&limit=50

GET ?action=detail&id={orderId}

ส่งคืนข้อมูลคำสั่งซื้อและ array items ที่มีสินค้า ราคา จำนวน และยอดต่อบรรทัด. ถ้าไม่พบ ส่ง 404.

GET ?action=dashboard

ส่งคืนจำนวนข้อมูลแต่ละตาราง, รายได้โดยประมาณ, topProducts, topCustomers และจำนวนคำสั่งซื้อรายเดือนใน monthly.

Write endpoints

ส่ง body เป็น JSON ผ่าน POST; ฟิลด์ที่กำหนดต้องครบและผ่าน validation รวมถึงการตรวจสอบ foreign key.

POST ?action=save

ไม่ส่ง id เพื่อสร้างรายการ; ส่ง id เพื่อแก้ไข. ตัวอย่างเพิ่มสินค้า:

{
  "entity": "products",
  "row": {
    "c_ProductName": "Chai",
    "i_SupplierID": 1,
    "i_CategoryID": 1,
    "c_Unit": "10 boxes x 20 bags",
    "i_Price": 18
  }
}

การแก้ไขใช้ body เดิมและเพิ่ม "id": 1. รองรับ CRUD ครบทั้ง 8 entities ในตารางด้านบน.

POST ?action=delete

{"entity":"products","id":1}

ลบ supplier/category/customer/employee/shipper/product ไม่ได้หากยังมีข้อมูลอื่นอ้างอิง; ลบ order จะลบ order details ใน transaction เดียวกัน.

Status codes

  • 200 สำเร็จ
  • 400 entity หรือ input ไม่ถูกต้อง
  • 401 ต้อง login หรือ credentials ไม่ถูกต้อง
  • 404 action, entity หรือ record ไม่พบ
  • 409 ลบไม่ได้เพราะมีข้อมูลอ้างอิง
  • 422 validation ไม่ผ่าน
  • 500 server/database error; รายละเอียดอยู่ใน server log

SQL safety

ค่าจาก client ผูกด้วย PDO prepared statements และปิด emulated prepares. ชื่อตาราง/คอลัมน์ dynamic เลือกจาก allowlist เท่านั้น; limit ถูกแปลงเป็น integer และจำกัดช่วง. อย่าต่อ input จากผู้ใช้เข้า SQL โดยตรง.
